# v0.2 — Evaluation & benchmark layer (wraps `gepa-ai/gepa`)

**Status:** scoped, not built. This is the layer that lets LoopGEPA honestly say
"optimized" — it *measures* whether a variant is better, instead of only
proposing it. It does not replace v0.1; it sits on top of the same genome, store,
and runner.

## The one design decision

**Do not reimplement evolutionary search or the Pareto frontier — wrap the
official GEPA optimizer.** GEPA already provides reflective mutation *and*
Genetic-Pareto candidate selection ([arXiv 2507.19457](https://arxiv.org/abs/2507.19457),
[gepa-ai/gepa](https://github.com/gepa-ai/gepa)). LoopGEPA's job is the *adapter*:
teach GEPA how to run and score a **loop genome**. This makes the "GEPA" in the
name literal and keeps the defensible IP in the trace schema, runner, and
loop-genome mapping (ADR-002).

## Mapping the loop genome onto GEPA

GEPA optimizes a `candidate: dict[str, str]` (named text components) against a
`trainset`, using a custom `GEPAAdapter` with two methods:

| GEPA concept | LoopGEPA mapping |
|---|---|
| `candidate: dict[str,str]` | the loop's **evolvable text genes** `{gene_id: content}` (skill, verifier_rubric, failure-summary, stop_condition text, retry policy serialized) |
| `trainset` (DataInst) | the **benchmark task set** — one instance per task the loop should handle |
| `adapter.evaluate(batch, candidate)` | build a genome from `candidate`, run the **LoopGEPA runner** per task, return `scores` + captured `LoopTrace` trajectories |
| `adapter.make_reflective_dataset(...)` | turn failing traces into GEPA's reflection dataset using our `failure_summary` + `infer_failure_modes` output |
| `reflection_lm` | the LLM that proposes mutations (Claude) |
| Pareto frontier | **provided by GEPA** — this is the deferred `pareto.py` from ADR-003, now free |

## Objectives (multi-objective, then scalarized for GEPA)

GEPA needs a scalar `score` per instance, but we keep the full vector for the
frontier and reporting: **success · cost · latency · diff size · retry count ·
human interventions · safety**. The scalar is success-dominant with tie-breaks
on cost/invasiveness. A promoted "optimized" variant reports the whole vector,
never a single number.

## Where the benchmark comes from

Three sources, in order of trust:

1. **Recorded traces (replay).** Each distinct task already in the store becomes a
   benchmark instance — "does this variant do better on the tasks that actually
   failed?" Zero authoring, honest, but limited to observed tasks.
2. **User-declared task set** — a `tasks/` folder of task specs + verifiers
   (the fully controlled benchmark).
3. **Held-out split** — reserve some tasks for validation to detect overfitting,
   exactly as GEPA recommends.

**LoopGEPA does not fabricate tasks out of nothing.** "Auto-benchmarking" means
*replaying your real traces / running your declared tasks*, not inventing a
synthetic suite.

## New MCP tools (v0.2)

`loopgepa_build_benchmark` (from traces or a tasks dir) ·
`loopgepa_evaluate_variant` (score one variant over the benchmark) ·
`loopgepa_optimize_loop` (run `gepa.optimize`, returns the frontier) ·
`loopgepa_get_frontier`.

## Honesty gates (unchanged discipline)

- Only after `evaluate` runs may output be labeled **optimized**.
- Every optimization run reports cost, latency, and variance across seeds.
- The research claim ("loop-level GEPA beats prompt-only GEPA") is earned only by
  the A/B/C/D comparison in IMPLEMENTATION §16 — not asserted before the data.

## Build order (v0.2)

1. `eval/objectives.py` — the metric vector + scalarizer (+ tests).
2. `eval/benchmark.py` — task set from traces / tasks dir (+ tests).
3. `eval/adapter.py` — `LoopGenomeAdapter` over `core.runner` (+ tests, offline
   with an injected executor).
4. `eval/optimize.py` — thin `gepa.optimize` wrapper returning the frontier.
5. MCP tools + docs + one worked optimization example.
6. The prompt-only-GEPA vs loop-level-GEPA benchmark writeup.

Dependency added only in v0.2: `gepa` (kept out of v0.1 so the core stays
network-free and dependency-light).
